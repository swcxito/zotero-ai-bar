# 代码审阅问题验证与修复（2026-10-16）

先在原实现上运行新增回归测试，再修复。测试通过代码驱动独立 Zotero 资料目录（`.scaffold/test`），未使用 computer use，也不访问付费模型。

| 问题                    | 修复前实测                                                        | 处理                                                                                                                                 |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 正则搜索阻塞            | `(a+)+$` 对 25 字符单行耗时约 2085ms                              | 使用纯 JS 的 RE2JS 非回溯引擎；同例约 2–3ms。明确不支持反向引用与环视，限制表达式长度，保留字面量检索与分页                          |
| 历史渲染竞态            | 更换会话后仍追加旧回答                                            | 使用递增渲染标记，在异步完成后检查标记、会话和连接状态；新建会话使旧渲染失效                                                         |
| 工具卡片样式冲突        | 实际背景为 page 的 `rgb(24,24,27)`，而 surface 为 `rgb(39,39,42)` | 通用背景映射排除工具卡片，保留组件指定的材质                                                                                         |
| Markdown 代码内容被改写 | 围栏、缩进代码中的引用变成可点击元素                              | 由 Marked token 区分代码和强调；在高亮前恢复代码字面量。保留表格引用标题和强调包装处理，代码中的行引用不再触发 PDF 读取              |
| 浮层交互不全            | 菜单顶部约 -76px，锚点移动后未翻转，Escape 不关闭                 | 使用 Floating UI 翻转、边缘修正、尺寸约束和定位更新；适配无 HTML body 的 XUL 文档，并在关闭时释放资源。补充 Escape、方向键和焦点返回 |
| 导航器重复测量          | 100 轮会话的滚动重复测量全部消息                                  | 缓存消息偏移，结构或内容尺寸变化时失效；滚动只复用几何信息                                                                           |
| 历史重复落盘            | 连续操作排入 21 次完整写入；flush 漏等后来写入                    | 合并连续变化；写入期间再变化只补写最终快照，flush 等待整个循环                                                                       |

发送/停止按钮状态合并到 `components/buttons/sendButton.ts`，输入组件和通用聊天 UI 不再为了按钮、滚动辅助函数依赖具体侧栏宿主。

## 未进行的重构

全量 Markdown 解析确实仍存在，但现有真实性能基准在修复前、修复后均通过。因此不将代码结构上的潜在开销视为已确认故障，不引入增量解析带来的语义风险。

修复后覆盖关闭皮肤和六种皮肤，约 8155、24465 字符样本；相对于整段 DOM 替换，测得最低中位耗时改善 61.8%，接收至布局完成 p95 为 17.67–42.95ms，达到已有的至少 40% 改善与不超过 100ms 延迟要求。这是本机合成流测试，不含接口网络等待及实际屏幕呈现。
