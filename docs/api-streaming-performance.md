# API 流式渲染优化验证

测试日期：2026-10-15。使用隔离 Zotero 配置、真实 Gecko DOM 和插件样式，未调用付费 API。

## 实现

- 完整解析 Markdown，在脱离页面的容器中生成候选内容，按绑定交互前的节点签名复用未变化的前后段落。保留引用、公式、表格及代码复制功能。
- 每次回答独立缓存公式和代码高亮；每类最多 128 项，合计最多 100 万字符，采用 LRU 淘汰。引用的 PDF 行号映射继续按回答复用。
- 根据渲染开销将刷新周期限制在 16–80ms；合并思考片段并追加到同一文本节点，在结束或停止时保存尾字。
- 流式自动滚动直接跟随最新内容，继续遵守用户暂停和长回答暂停规则；历史消息跳转保留平滑滚动。

## 对比结果

约 8155 字符样本含中文段落、标题、行内公式和表格。每种条件重复两轮，每轮 20 次递增更新，交替运行旧方式和新方式以减小顺序偏差。耗时包含 Markdown 解析、DOM 更新和强制布局；以下为单次更新中位数。

| 皮肤        | 整段替换（ms） | 优化后（ms） | 耗时降低 | 接收至布局完成 p95（ms） |
| ----------- | -------------: | -----------: | -------: | -----------------------: |
| 关闭        |          21.85 |         8.19 |    62.5% |                     27.9 |
| Rose        |          18.96 |         6.88 |    63.7% |                     33.0 |
| Paper       |          19.49 |         6.70 |    65.6% |                     18.7 |
| Neumorphism |          22.86 |         7.46 |    67.4% |                     17.7 |
| Moss        |          19.93 |         6.59 |    66.9% |                     17.8 |
| Tactical    |          19.21 |         6.98 |    63.7% |                     18.2 |
| BW          |          19.45 |         7.28 |    62.6% |                     18.2 |

24465 字符样本的更新中位耗时从 53.38–63.36ms 降至 17.11–18.85ms，各条件降低约 66.7%–71.7%。

延迟测试在每种显示条件下以 5ms 间隔注入 120 次文字更新，通过实际自适应调度器渲染；被合并的更新也计入延迟。七种条件均达到「中位更新耗时降低至少 40%」及「p95 延迟不超过 100ms」的验收目标。

这些数据衡量本机合成流的 DOM 提交及布局完成时间，不包含接口网络等待和屏幕实际呈现。完整 Markdown 及候选 DOM 仍会解析，极长的单个段落、列表或代码块仍可能带来更高耗时。

## 复现和回归

```sh
pnpm test:codex
pnpm test:codex-zotero --all
pnpm test:codex-zotero --perf
pnpm build
```

性能测试为独立可选入口，输出原始逐次耗时及汇总至 `.scaffold/test/profile/api-stream-performance.json`。它使用 `.scaffold/test` 的隔离配置，不使用用户的 Zotero 数据库。

验证通过：59 项本地测试、148 项隔离 Zotero 测试、性能验收，以及构建、类型检查、修改文件的格式和 ESLint 检查。逐字符测试比较每一步与完整渲染的结果，覆盖未闭合公式／代码、表格、嵌套列表和后置链接定义；另有节点和交互复用、缓存隔离与容量、工具和思考边界、停止及错误尾字、过期异步提交、自动滚动及选择复制的回归测试。
